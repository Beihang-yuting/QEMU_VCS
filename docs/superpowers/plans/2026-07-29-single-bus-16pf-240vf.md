# Single-Bus 16 PF + 240 VF Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a one-bus 16-PF/240-VF ARI profile while preserving the existing one-PF/16-VF and smaller multi-PF behavior.

**Architecture:** PF0 owns one transport and creates PF1 through PF15 as sibling QEMU PCIe functions at raw devfn values 1 through 15. The VIP owns config space and assigns interleaved VF RIDs with `FirstVFOffset=VFStride=NUM_PFS`; the 16-PF profile limits each PF to 15 VFs, filling devfn 0 through 255 without crossing a bus.

**Tech Stack:** C11 bridge ABI, QEMU PCI/PCIe device model, SystemVerilog/UVM PCIe VIP, Bash/CMake tests, Synopsys VCS, Linux PCI/SR-IOV tools.

### Task 2: Implement Shared Limits and VIP BDF Arithmetic

**Files:**
- Modify: `bridge/common/cosim_topology.h`
- Modify: `pcie_tl_vip/src/shared/pcie_tl_func_manager.sv`
- Modify: `vcs-tb/cosim_runtime_policy_pkg.sv`
- Modify: `vcs-tb/cosim_xrc_driver.sv`

- [ ] **Step 1: Expand the shared C topology and add pure helpers**

Set `COSIM_MAX_PFS` to 16 and add overflow-safe helpers equivalent to:

```c
static inline uint16_t cosim_pf_rid(uint16_t base, unsigned pf) {
    return (uint16_t)(base + pf);
}
static inline uint16_t cosim_vf_rid(uint16_t pf_rid, unsigned offset,
                                    unsigned stride, unsigned vf) {
    return (uint16_t)(pf_rid + offset + vf * stride);
}
static inline int cosim_single_bus_profile_fits(unsigned pf0_devfn,
                                                unsigned num_pfs,
                                                unsigned vfs_per_pf) {
    uint32_t last;
    if (num_pfs == 0) return 0;
    last = pf0_devfn + num_pfs - 1;
    if (vfs_per_pf > 0) last += num_pfs * vfs_per_pf;
    return num_pfs > 0 && num_pfs <= COSIM_MAX_PFS && last <= 255;
}
```

Handle `vfs_per_pf == 0` without underflow.

- [ ] **Step 2: Preserve all eight PF devfn bits in the VIP**

Replace the bootstrap concatenation using `pf[2:0]` with
`pcie_pf_bdf(base_bdf, pf)`. Keep runtime rebinding on the same helper and add
a hard failure when the 16-PF profile tries to bind PF0 at a non-zero devfn.

- [ ] **Step 3: Expand and constrain VCS launch policy**

Change `cosim_valid_num_pfs` to accept 1 through 16. Add:

```systemverilog
function automatic bit cosim_single_bus_profile_fits(
    input int num_pfs, input int max_vfs);
    int last_devfn;
    if (num_pfs < 1 || max_vfs < 0) return 0;
    if (max_vfs == 0) return num_pfs <= 256;
    last_devfn = num_pfs * (max_vfs + 1) - 1;
    return last_devfn <= 255;
endfunction
```

In `cosim_xrc_driver.sv`, reject `NUM_PFS=16,MAX_VFS>15`; do not apply this
new restriction to existing configurations such as 4 PF x 256 VF, because
their previously supported cross-bus behavior must remain intact.

- [ ] **Step 4: Run the standalone SV and C unit tests**

Expected: RID arithmetic tests pass; launch-source test still fails until the
QEMU and Makefile changes land.
